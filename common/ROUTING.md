# common 라우팅 규약

`common` 플러그인의 **라우터 스킬**이 공통으로 따르는 규약. 각 라우터 SKILL.md는 위임 대상 표와 자기 특이사항만 정의하고, 절차는 이 문서를 canonical로 삼는다.

라우터는 **절차를 갖지 않는다.** 실제 동작은 위임 대상 하네스 스킬이 정의하며, 라우터는 "어느 하네스로 보낼지"만 결정한다.

## 왜 라우터인가

같은 이름의 스킬이 하네스마다 존재한다(`/be-harness:request`, `/fe-harness:request`, …). 사용자가 매번 어느 하네스인지 기억해 접두를 붙이는 대신, `/common:request` 하나로 진입하고 대상은 플래그나 선택지로 정한다.

## 대상 플래그 (전 라우터 공통)

| 플래그 | 단축 | 하네스 |
|--------|------|--------|
| `--be` | | `be-harness` — 범용 백엔드 |
| `--fe` | | `fe-harness` — 범용 프론트엔드 |
| `--fs` | | `fs-harness` — 풀스택 오케스트레이터 |
| `--mm` | | `minmos-harness` — minmos 프로젝트 전용 |
| `--hd` | | `hyeondongs-harness` — hyeondongs 프로젝트 전용 |

- 플래그는 **인자 어느 위치에나** 올 수 있다. 라우터는 플래그를 제거한 나머지 인자를 그대로 대상에 전달한다.
- 대상 스킬 고유 플래그(`--hard`, `--analyze`, `--dry-run` 등)는 **해석하지 않고 그대로 넘긴다.**
- 두 개 이상의 대상 플래그가 오면 오류로 처리한다: "대상 플래그는 하나만 지정하세요: {입력된 목록}".
- 한 하네스가 같은 이름의 변형을 둘 이상 제공하면(예: minmos의 `start-workflow-mm`과 `start-workflow-fs`) 라우터가 **자기 표에 추가 플래그를 정의**한다(`--mm-fs` 등). 추가 플래그도 위 규칙을 그대로 따른다.

## 실행 절차

```
1. 대상 플래그 파싱
2. 후보 산출 — 위임 대상 표의 스킬 중 세션 스킬 목록에 실제로 존재하는 것만
3. 분기:
   - 플래그 있음 + 후보에 존재  → 즉시 위임 (4번)
   - 플래그 있음 + 후보에 없음  → 미설치 안내 후 종료
   - 플래그 없음 + 후보 0개     → 미설치 안내 후 종료
   - 플래그 없음 + 후보 1개     → 고지 후 즉시 위임
   - 플래그 없음 + 후보 2개 이상 → 선택지 제시 (아래) → 위임
4. 위임: Skill tool로 대상 스킬을 호출하고, 플래그를 제거한 인자를 그대로 전달
```

### 후보 산출

세션에 로드된 스킬 목록에서 대상 스킬 이름의 존재 여부로 판단한다. 플러그인은 개별 설치되므로 **표의 대상이 항상 존재한다고 가정하지 않는다.**

### 선택지 제시 (플래그 없음 · 후보 2개 이상)

프로젝트 신호로 **권장 후보를 표시하되, 결정은 항상 유저가 한다.** 신호만 보고 조용히 실행하지 않는다.

| 신호 | 권장 대상 |
|------|----------|
| `.claude/be-harness.local.md` 존재 | `--be` |
| `.claude/fe-harness.local.md` 존재 | `--fe` |
| `.hyeondong-config.json` 존재 | `--hd` |
| 위 셋 중 둘 이상 존재 | `--fs` (풀스택 작업일 때) |
| 신호 없음 | 권장 표시 없이 후보만 나열 |

`AskUserQuestion`으로 후보를 제시한다. 각 선택지에 하네스 이름과 한 줄 설명을 넣고, 권장 후보는 라벨 끝에 `(권장)`을 붙인다.

`AskUserQuestion`을 쓸 수 없는 컨텍스트(서브에이전트 등)에서는 번호 매긴 선택지를 출력하고 유저 응답을 기다린다:

```
어느 하네스로 실행할까요?
1. be-harness — 범용 백엔드 (권장: .claude/be-harness.local.md 발견)
2. fe-harness — 범용 프론트엔드
3. 취소
```

### 미설치 안내 (graceful degradation)

| 감지 | 폴백 | 고지 문구 |
|------|------|----------|
| 지정한 플래그의 대상 스킬이 세션에 없음 | 종료 | "`{플러그인}` 이 설치되어 있지 않습니다. `/plugin install {플러그인}@harness-plugins` 로 설치하거나, 설치된 하네스를 지정하세요: {후보 목록}" |
| 후보가 하나도 없음 | 종료 | "이 스킬을 제공하는 하네스가 하나도 설치되어 있지 않습니다. 필요한 플러그인을 먼저 설치하세요: {표의 플러그인 목록}" |

## 위임 후 동작

- 라우터는 대상 스킬의 출력을 **가공하지 않고 그대로** 전달한다. 요약·재구성 금지.
- 대상 스킬이 `SKIPPED:*` / `BLOCKED:*` 를 반환하면 그대로 상위에 올린다.
- 라우터는 상태 파일을 만들거나 갱신하지 않는다.

## 라우터가 하지 않는 것

- 대상 스킬의 절차를 복제하지 않는다 (복붙 금지 — `docs/skill-authoring.md` §9).
- 대상 스킬 고유 플래그를 해석하거나 검증하지 않는다.
- 프로젝트 신호만으로 대상을 확정하지 않는다 (후보가 1개일 때 제외).

## 대상이 하나뿐인 스킬

위임 대상이 하나인 스킬은 라우터를 만들지 않는다. 그 하네스 스킬을 직접 호출한다.

## 하네스 간 차이가 없는 스킬

동작이 하네스와 무관한 스킬(`how-to-use`, `submit-feedback`)은 라우터가 아니라 **common이 직접 구현**한다. 이 경우 대상 플래그는 동작을 바꾸는 스위치가 아니라 **범위를 좁히는 선택적 필터**로만 쓰인다.
